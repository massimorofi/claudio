# Claudio backend benchmark

Harness artifacts (`runner.py` + `judge.py`) plus a stdlib-only aggregator that
turns them into one KPI summary (`aggregate.py`).

```
benchmark/
├── aggregate.py            # run.json + judge.json + capability.json -> summary.json
├── runner.py               # writes results/<backend>/<task_id>/trial_<k>/
├── judge.py                # writes judge.json next to each run.json
├── results/
│   ├── capability.json     # harness-wide availability + engine mode per backend
│   ├── judge_key.json      # blind-review key (backend <-> letter)
│   ├── <backend>/<task_id>/trial_<k>/
│   │   ├── run.json        # one measured run (required)
│   │   ├── judge.json      # rubric scores (optional)
│   │   ├── diff.patch, verify.txt, prompt.txt, stdout.txt, stderr.txt, session.jsonl
│   └── summary.json        # generated by aggregate.py
└── tests/test_aggregate.py # exact mean/median/pass-rate/winners assertions
```

Backends: `google_adk`, `claude_code`, `opencode`.
Categories: `bug_fix`, `feature`, `refactor_debug`, `codebase_qa`.

> **Note on the committed tree.** The `results/**` files checked into git are
> deterministic *stub-engine* artifacts (one trial per backend per task, 21 runs)
> so CI can run the aggregator end-to-end without live model calls.
> `capability.json` records that no real engine binary was reachable, hence
> `engine_mode: "stub"` and `available: false` for all three backends. A real
> harness run writes the same files and simply overwrites them.

## Input schemas

`run.json` (all keys optional; missing numbers default to `0`, missing flags to
`false`):

| key | meaning |
|---|---|
| `backend`, `task_id`, `trial` | grouping keys; also inferred from the path |
| `category` | optional override; otherwise inferred from `task_id` (see below) |
| `engine_mode` | e.g. `native`, `cli_bridge`, `stub` (`capability.json` wins) |
| `verification_passed` | bool — feeds `pass_rate` |
| `tokens.input` / `.output` / `.total` | token counts; `total` defaults to `input + output`; `input_tokens`/`output_tokens`/`total_tokens` are accepted aliases |
| `errors.command_errors` / `.tool_errors` / `.retries` / `.timeouts` | per-run error counters |
| `duration_s` | run wall clock (aliases `wall_clock_seconds`, `wall_clock`) |

`judge.json`: `{"scores": {"quality": 3, "intelligence": 2, "coding": 3}}`
(`rubric.{...}` and a flat `{quality: ...}` are accepted too). A run with no
`judge.json` contributes nothing to the rubric statistics.

`capability.json`: either the harness-wide report
`{"backends": {"<backend>": {"available": false, "engine_mode": "stub"}}}` or a
single-run report `{"available": ..., "engine_mode": ...}`. Both are read; a file
next to a `run.json` overrides the harness-wide entry for that run.

## Category resolution

`run.json` stores a `task_id`, not a category, so `aggregate.py` resolves it as:

1. an explicit `category` in `run.json`, else
2. `--category-map <file.json>` (`{"<task_id>": "<category>"}`), else
3. a substring rule on the task id: `refactor_`/`_debug`/`debug_` →
   `refactor_debug`, `fix_`/`bug_`/`_bug` → `bug_fix`,
   `add_`/`implement_`/`feature_` → `feature`,
   `qa_`/`explain_`/`describe_`/`where_` → `codebase_qa`, else `uncategorized`.

The four canonical categories are **always** present in `categories`; one with no
runs maps to `{}`. In the committed tree the stub task set covers `bug_fix`
(6 tasks × 3 backends) and `feature` (1 task × 3 backends); `refactor_debug` and
`codebase_qa` are reported empty until such tasks are run.

## Rubric sampling

`rubric.{quality,intelligence,coding}` (and `categories[...]["rubric_mean"]`)
average **judged runs only**. A run without a `judge.json` still counts towards
`n_runs`, `pass_rate`, `tokens`, `errors` and `wall_clock`, but contributes no
rubric sample, so an unjudged run cannot pull a backend's quality down towards
zero. A backend with no judged run at all reports `0.0` and is ineligible to win
that dimension.

## Running

```bash
python3 benchmark/aggregate.py --results benchmark/results \
    --out benchmark/results/summary.json
```

Exit `0` and a compact markdown summary table on stdout (the progress line goes
to stderr, so stdout stays pipeable); `--quiet` suppresses the table; exit `1`
when no `run.json` exists under `--results`. `--out` defaults to
`<results>/summary.json`.

Rendered for the committed tree:

```markdown

| backend | mode | avail | n | pass rate | tokens total mean/median | errors total/mean | wall clock s mean/median | rubric Q/I/C mean |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| google_adk | stub | no | 7 | 100.0% | 3165.43 / 2951 | 4 / 0.57 | 0.160 / 0.160 | 2.71 / 2.71 / 3 |
```

## summary.json shape

```jsonc
{
  "generated_at": "2026-11-26T01:35:50Z",
  "n_runs": 21,
  "backends": {
    "google_adk": {
      "available": false,
      "engine_mode": "stub",                 // modal value across the backend's runs
      "n_runs": 7,
      "pass_rate": 1.0,                      // verification_passed true / n_runs (0..1)
      "tokens": {"input":  {"mean": 1906.8571, "median": 1790.0},
                 "output": {"mean": 604.7143,  "median": 560.0},
                 "total":  {"mean": 3165.4286, "median": 2951.0}},
      "errors": {"command_errors": 1, "tool_errors": 1, "retries": 2, "timeouts": 0,
                 "total": 4, "mean_per_run": 0.5714},
      "wall_clock": {"mean": 0.1601, "median": 0.16},
      "rubric": {"quality":      {"mean": 2.7143, "median": 3.0},
                 "intelligence": {"mean": 2.7143, "median": 3.0},
                 "coding":       {"mean": 3.0,    "median": 3.0}}
    }
  },
  "categories": {
    "bug_fix": {
      "google_adk": {"n_runs": 6, "pass_rate": 1.0,
                     "tokens_total_median": 3101.5, "rubric_mean": 2.7778}
    },
    "feature": { }, "refactor_debug": { }, "codebase_qa": { }
  },
  "winners": {"tokens": "google_adk", "quality": "claude_code", "errors": "claude_code",
              "intelligence": "claude_code", "coding": "claude_code"}
}
```

Conventions:

* `mean`/`median` use `statistics.fmean` / `statistics.median`; all floats are
  rounded to 4 decimals. Error counts stay whole numbers, `mean_per_run` does not.
* `rubric_mean` in `categories` is the mean over **all** rubric dimensions of all
  judged runs in that (category, backend) cell.
* `winners`: `tokens` = lowest mean total tokens, `errors` = lowest
  `errors.mean_per_run`, `quality`/`intelligence`/`coding` = highest rubric mean.
  Only backends with `available: true` compete (if none is, all compete — which is
  the case for the stub tree). A rubric mean of `0` means "nothing was judged" and
  is excluded, while a zero error rate is a real (winning) result. Ties break
  alphabetically so the block is deterministic.
* A backend/category with no data reports `0` / `0.0` rather than `null`, so
  downstream consumers can always do arithmetic.

## Tests

```bash
PYTHONPATH=benchmark python3 -m pytest benchmark/tests/test_aggregate.py -q
```

The tests build a tiny synthetic tree in `tmp_path` with hand-computed
means/medians (chosen so median ≠ mean) and assert the full `backends`,
`categories` and `winners` blocks **key-for-key against the schema above**, the
availability filter and alphabetical tie-breaking, fallbacks for missing
`judge.json` / `capability.json` / `tokens.total`, that unjudged runs are
excluded from rubric means, `--category-map`, the markdown table, the CLI exit
codes, and — as an end-to-end check — that the committed tree satisfies the
summary contract.
