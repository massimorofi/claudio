# Claudio backend benchmark

Artifacts produced by the benchmark harness, plus the stdlib-only aggregator
that turns them into a KPI summary.

```
benchmark/
├── aggregate.py                  # run.json + judge.json + capability.json -> summary.json
├── results/
│   ├── <category>/<backend>/<run_id>/run.json         # one measured run (required)
│   ├── <category>/<backend>/<run_id>/judge.json       # rubric scores (optional)
│   ├── <category>/<backend>/<run_id>/capability.json  # availability + engine mode (optional)
│   └── summary.json              # generated by aggregate.py
└── tests/test_aggregate.py       # exact mean/median/winners assertions
```

Categories: `bug_fix`, `feature`, `refactor_debug`, `codebase_qa`.
Backends: `google_adk`, `claude_code`, `opencode`.

> **Note on the committed tree.** The `results/**` files checked into git are
> deterministic *seed* data (2 runs per backend per category, 24 runs) that
> pin the aggregator's behaviour and let CI run the summary end-to-end without
> live model calls. A real harness run writes the same three files per run
> directory and simply overwrites them.

## Input schemas

`run.json` (all keys optional; missing numbers default to `0`, missing flags to
`false`):

| key | meaning |
|---|---|
| `backend`, `category`, `run_id` | grouping keys; also inferred from the path |
| `engine_mode` | e.g. `native`, `cli_bridge` (overridden by `capability.json`) |
| `available` | did the backend run at all (overridden by `capability.json`) |
| `verification_passed` | bool — feeds `pass_rate` |
| `tokens.input` / `tokens.output` / `tokens.total` | token counts; `total` defaults to `input + output`; `input_tokens`/`output_tokens`/`total_tokens` are accepted aliases |
| `errors.command_errors` / `.tool_errors` / `.retries` / `.timeouts` | per-run error counters |
| `wall_clock_seconds` | run duration (alias `wall_clock`) |

`judge.json`: `{"rubric": {"quality": 4.5, "intelligence": 4.0, "coding": 4.5}}`
(flat `{"quality": ...}` also accepted). A run with no `judge.json` contributes
nothing to rubric statistics.

`capability.json`: `{"available": true, "engine_mode": "cli_bridge"}`.

## Running

```bash
python3 benchmark/aggregate.py --results benchmark/results \
    --out benchmark/results/summary.json
```

Exit `0` and a compact markdown table on stdout (progress line goes to stderr,
so stdout stays pipeable); `--quiet` suppresses the table; exit `1` when no
`run.json` exists under `--results`.

## summary.json shape

```jsonc
{
  "generated_at": "2026-11-26T01:15:09+00:00",
  "n_runs": 24,
  "backends": {
    "<backend>": {
      "available": true,
      "engine_mode": "cli_bridge",          // modal value across the backend's runs
      "n_runs": 8,
      "pass_rate": 0.75,                    // verification_passed true / n_runs (0..1)
      "tokens":  {"input": {"mean": 0, "median": 0},
                  "output": {"mean": 0, "median": 0},
                  "total":  {"mean": 0, "median": 0}},
      "errors":  {"command_errors": 0, "tool_errors": 0, "retries": 0,
                  "timeouts": 0, "total": 0, "mean_per_run": 0.0},
      "wall_clock": {"mean": 0.0, "median": 0.0},
      "rubric":  {"quality": {"mean": 0.0, "median": 0.0},
                  "intelligence": {"mean": 0.0, "median": 0.0},
                  "coding": {"mean": 0.0, "median": 0.0}}
    }
  },
  "categories": {
    "<category>": {
      "<backend>": {"n_runs": 2, "pass_rate": 1.0,
                    "tokens_total_median": 6313.5, "rubric_mean": 3.5333}
    }
  },
  "winners": {"tokens": "opencode", "quality": "claude_code",
              "errors": "google_adk", "intelligence": "opencode",
              "coding": "claude_code"}
}
```

Conventions:

* `mean`/`median` use `statistics.fmean` / `statistics.median`; all floats are
  rounded to 4 decimals. Error counts stay whole numbers, `mean_per_run` does not.
* `rubric_mean` in `categories` is the mean over **all** rubric dimensions of all
  judged runs in that (category, backend) cell.
* `winners`: `tokens` = lowest mean total tokens, `errors` = lowest
  `errors.mean_per_run`, `quality`/`intelligence`/`coding` = highest rubric mean.
  Only backends with `available: true` compete (if none is, all compete), and ties
  break alphabetically so the block is deterministic.
* A backend/category with no data reports `0` / `0.0` rather than `null`, so
  downstream consumers can always do arithmetic.

## Tests

```bash
PYTHONPATH=benchmark python3 -m pytest benchmark/tests/test_aggregate.py -q
```

The tests build a tiny synthetic tree in `tmp_path` with hand-computed
means/medians (chosen so median ≠ mean) and assert the full `backends`,
`categories` and `winners` blocks, plus fallbacks for missing `judge.json` /
`capability.json` and a missing `tokens.total`.
